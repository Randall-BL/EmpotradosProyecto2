# CD-08 — Switches: encuesta o interrupción, y asignación a filtros

- **Responsable:** C · **Fecha:** 2026-11-03 · **Estado:** decidido
- **Requisito:** selección de 3 filtros con switches durante la reproducción, con el
  cambio audible en menos de 100 ms (§3-F p.4, §3-SIS p.5).

## Alternativas de lectura

| | A. Encuesta cada 20 ms desde el lazo principal | B. Interrupción por flanco (`pio_sw`, IRQ 3) |
|---|---|---|
| Latencia | ≤ 20 ms + confirmación (20 ms) + FIFO del códec (2.7 ms) ≈ 43 ms | ~µs + FIFO (2.7 ms) |
| Rebote del switch | Se filtra pidiendo dos lecturas iguales seguidas (20 ms) | Cada rebote es una IRQ; hace falta un antirrebote igual |
| CPU | Una lectura de PIO cada 20 ms (despreciable) | Una ISR por flanco, incluidos los rebotes |
| Complejidad | Una función en el lazo (`sw_update`) | ISR + cola + el mismo antirrebote |
| Prueba en el PC | `test_input`, `test_app` con un reloj simulado | Necesita simular la ISR |

Los switches de la DE1-SoC no tienen antirrebote (a diferencia de los KEY), así que la
interrupción no ahorra el filtrado. El requisito es 100 ms: la encuesta deja más de la
mitad de margen.

## Decisión de lectura

**Alternativa A**, encuesta cada `SW_POLL_MS = 20 ms` en `app_step()`. El cambio se
acepta cuando dos lecturas seguidas coinciden (`sw_update`, `sw/common/src/switches.c`).
La IRQ de `pio_sw` queda en el SoC (HW-02) pero la aplicación no la habilita.

Medido en `test_app` (reloj simulado, FIFO de 128 cuadros a 48 kHz): el filtro cambia en
el hardware **≤ 41 ms** después de mover el switch, en los cuatro casos.

## Asignación

Un switch por filtro, para que el usuario vea en la tarjeta cuál está activo:

| SW2 | SW1 | SW0 | Filtro | Dónde |
|---|---|---|---|---|
| 0 | 0 | 0 | Bypass (sin filtro) | Módulo propio en bypass (solo ganancia) |
| 0 | 0 | 1 | Pasa-bajos 1 kHz | Módulo propio, banco 0 |
| 0 | 1 | 0 | Pasa-banda 1–4 kHz | Módulo propio, banco 1 |
| 1 | 0 | 0 | Reverberación 50 ms | Software en el Nios V (`dsp_reverb`, CD-12); módulo en bypass |
| dos o más arriba | | | **Inválida:** bypass y LEDR9 encendido | La pantalla dice "SW INVALIDO" |

SW[9:3] no se usan. Ante una combinación inválida se elige bypass (y no "el último
filtro válido") para que lo que suena coincida siempre con lo que dicen los LEDs y la
pantalla, sin depender del orden en que se movieron los switches.

## LEDs

| LEDR | Significado |
|---|---|
| 0, 1, 2 | Filtro activo (uno encendido a la vez; ninguno = bypass) |
| 5 | Hubo al menos un subdesborde de audio (PR-08) |
| 6 | Cambia con cada botón aceptado (medición de respuesta, PR-07) |
| 7 | Reproduciendo |
| 8 | Pausado |
| 9 | Alerta: switches inválidos, el HPS no encontró la SD o ninguna pista se pudo leer |

## Consecuencias

- `test_filtros` (persona B) usaba SW[1:0] codificados en binario de forma provisional;
  la aplicación final (`sw/niosv/src`) usa esta tabla. La prueba de B no cambia porque
  es un programa aparte.
- Verificado en el PC (`test_input`, `test_app`) y en la co-simulación del Nios V
  (`tb_player`: LEDR[2:0] y LEDR9 con cada combinación).
