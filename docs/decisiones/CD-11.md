# CD-11 — Máquina de reproducción: software o hardware

- **Responsable:** C · **Fecha:** 2026-11-03 · **Estado:** decidido
- **Requisito:** control de reproducción con 4 botones (play/pausa, stop, anterior,
  siguiente), avance automático y estados visibles (§3-F p.3, §3-SIS p.6).

## Alternativas

| | A. FSM en software (`sw/common`) | B. FSM en hardware (HDL) |
|---|---|---|
| Eventos que atiende | Botones, fin de pista y errores que llegan del HPS por la memoria compartida | Los botones directamente; el fin de pista y los errores igual vienen del software |
| Acciones | Pedir pistas al HPS, vaciar el flujo, redibujar: todo es software | Tendría que avisar al software de cada cambio (IRQ o registro de estado) |
| Latencia | Una vuelta del lazo principal (µs) | Ciclos, pero la acción la ejecuta el software igual |
| Recursos | ~450 B de código (`fsm_handle`) | ALMs + registros + interfaz Avalon + su testbench |
| Prueba | En el PC con 20 000 eventos aleatorios (`test_fsm`) | Testbench HDL y co-simulación |
| Cambios | Una fila de la tabla | Resintetizar (~10 min de Quartus) |

## Decisión

**Alternativa A.** La FSM es una tabla `[estado][evento]` en `sw/common/src/fsm.c` que
devuelve acciones (`FSM_ACT_*`) y no toca hardware. Todo lo que la rodea (pedir la pista
al HPS, el flujo de audio, la pantalla) ya es software, así que una FSM en hardware solo
movería la decisión lejos de quien la ejecuta. El hardware propio se dedica al filtro y
la ganancia (CD-04, CD-05), donde sí ahorra CPU.

Estados: DETENIDO, REPRODUCIENDO, PAUSADO. Eventos: play/pausa (KEY0), stop (KEY1),
anterior (KEY2), siguiente (KEY3), fin de pista y error. La tabla completa está en el
encabezado de `sw/common/include/fsm.h` y en el documento de software (DOC-01).
